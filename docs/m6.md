# M6 — Threads apart from provider sessions

Implemented from page 50 of the
[Kru project plan](Kru%20%E2%80%94%20Project%20Plan%20%26%20Milestones.pdf).
An agent lane now owns a durable Kru thread. Native Claude/Codex session ids
are replaceable bindings; the conversation stays in Kru when the provider,
model, instructions or native cache changes.
Released as **v0.1.1**; the roadmap reserves v0.2.0 for M7.

## Try it

```sh
bun run demo:handoff
bun run test:threads
```

The demo runs ten sequential turns through the Claude adapter, calls the actual
`agent set teammate --provider codex` CLI in another process, then runs a Codex
turn that calls `history_search` for the first-turn launch code. It asserts one
logical thread, eleven linked completed turns, a fresh native session, bounded
handoff, successful retrieval and replay parity. Claude uses scripted SDK messages
and its real local MCP server; Codex uses its real adapter over a scripted stdio
peer. **Zero live model calls:** this verifies storage and protocol integration,
not live model recall quality. [Recorded evidence](verification/m6-demo-2026-11-05.json)
includes the actual handoff, search answer, bindings and assertions.

With configured native provider logins and a running daemon:

```sh
bun run dev -- agent set reviewer --provider codex
bun run dev -- send reviewer "What did we decide in our first conversation?"
bun run dev -- log reviewer --follow
```

A provider-only switch clears the inherited model so the destination provider
can select its default. An inherited Claude `full` profile becomes `minimal`
when moving away from Claude; explicit `--model`/`--prompt-profile` replacements
are retained. Instructions, permissions and budgets remain the agent's settings.

## Identity and replacement

Migration **v7** adds `threads`, unique by `(agent_id, lane_key)`, and
`turn_threads`, linking each durable turn to its logical thread without changing
the shipped `turn.prepared` payload. It renames `agent_sessions` to
`provider_sessions` and adds the logical thread id, active flag and
`handoff_pending` marker. A partial unique index permits one active provider
binding per logical thread. M3's `active_lanes` still enforces one executing
batch per lane.

The migration discovers existing lanes from deliveries, turns and bindings,
appends `thread.created` and `turn.thread_linked` events, and preserves old
events and native ids. The newest binding in a lane becomes active; equal
timestamps prefer the agent's configured provider. Existing bindings start
without a pending handoff. The complete upgrade and its migration marker commit
together; a failed upgrade rolls back and can be retried.

New thread identities and turn links are event-sourced. Replay now compares
**eleven** projection tables. Native bindings remain operational state, like
locks and scratch snapshots: replay cannot recreate a provider's native cache.

For a compatible active binding, startup tries `thread/resume` first. Only a
known missing/retired native-session error triggers replacement. Transient RPC
errors keep the binding and hold work for recovery. Configuration changes and
provider switches create a fresh native session with handoff. Switching back
also creates a fresh session rather than resuming an inactive cache that missed
intervening turns.

A new binding keeps `handoff_pending=1` until a confirmed `turn/started`, cleared
inside the same transaction that records the native turn and marks its batch
running. A daemon stopping after setup but before submission therefore retains
the pending handoff. Successful resume of a session that already received its
handoff does not inject history again. Unknown submitted work retains the
existing interrupted/no-automatic-retry rule; M7 remains the crash-recovery milestone.

## Bounded handoff

The default packet budget is **6,000 characters**, including wrappers, ids and
JSON escaping. `daemon --handoff-chars <count>` accepts 512–16000. The packet also
fits the remaining UTF-8 bytes of the existing 32 KiB turn-input limit. If even
the wrapper cannot fit alongside the current request, that delivery fails with
a clear smaller-message error before provider submission; the binding still
needs its handoff for the next request.

Kru reads the first two conversation records and at most forty recent records,
pins the early anchors, then fills remaining space from newest to oldest.
Selected records render in durable delivery/item sequence order, independent
of clock changes. Each excerpt is capped (750 characters for early anchors,
700 for others), labelled with its status/partial flag and clipped marker.
Unicode pairs stay intact. These are excerpts, not generated summaries.

History is prepended only to the replacement session's next turn input, before
an explicit current-request boundary. Dynamic history stays out of the stable
instruction/tool prefix. Current batch messages, queued/cancelled deliveries
and inputs rejected before execution are excluded. Interrupted/failed native
turns remain available with their status. The packet contains conversation text;
selected native tool/command/file details are available through search instead
of filling the packet. Native reasoning is excluded.

## History tool

The daemon now registers `history_search` alongside `list_agents` and
`send_message`, within the existing six-tool/8,000-byte declaration limits.
The scheduler derives its scope from the confirmed owning agent, lane and
native turn. There are no model-supplied agent/thread/lane selectors.

```json
{ "query": "launch code", "limit": 5 }
```

Search is literal, case-insensitive using JavaScript Unicode lowercasing,
without wildcard syntax, embeddings or model calls. Queries contain 1–200
characters; results default to five, with a maximum of five. Newest matches
come first. Pass `nextCursor` as `cursor` with the same query for older matches.
Cursors are checked against the calling thread and query; even forged ordering
values cannot change the SQL ownership scope.

Search snippets are at most 800 characters plus ellipses, and serialized pages
stay below 8,000 characters. User/input results can include a bounded answer
excerpt and `relatedEntryId`, linking the corresponding final assistant item.
The related answer excerpt participates in matching so a question can lead
back to its answer.

```json
{ "entryId": "item:1", "offset": 800 }
```

Use a returned entry id to read its full stored text in chunks of at most 800
characters. Continue with `nextOffset` until it is null. Search parameters and
entry/offset parameters are mutually exclusive. This keeps full retrieval in
one tool rather than adding a separate `history_read` declaration. Foreign
entry ids return no records; invalid arguments/cursors produce unsuccessful
tool results without killing the daemon. M5's active-owner checks, cancellation
and durable native-call receipts also apply to history calls.

Library hosts can use `ThreadStore`, `SqliteHistory` and `handoffPacket` through
the `kru/threads` export. The default daemon wires these automatically. Custom
scheduler hosts must supply the handoff/acknowledgement SessionStore methods
and history-aware tools to obtain the same behavior; legacy custom ports remain
compatible without these optional methods.

## Read-after comparison

After implementation, reviewed OpenBot's pinned
[ensureThread](https://github.com/nightly-labs/openbot/blob/0b311bf/src/backend/agent/thread-lifecycle.ts),
[handoff construction](https://github.com/nightly-labs/openbot/blob/0b311bf/src/backend/agent/handoff-history.ts)
and [history retrieval architecture](https://github.com/nightly-labs/openbot/blob/0b311bf/docs/architecture/providers.md#history-retrieval-and-replacement-sessions).
The comparison reinforced stable public identities, resume before replacing,
pending handoffs, bounded excerpts, Unicode-safe cuts and strict conversation
ownership. Kru uses a smaller packet to fit its existing 32 KiB input cap,
preserves early conversation anchors alongside recent context, and provides
full entry continuation in `history_search`. Context-reset/branch APIs,
captured provider work-step files and semantic summaries are outside M6.
